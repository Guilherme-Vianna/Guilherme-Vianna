01 · Agendamento para barbearias

Navalha

Agenda online para barbearias: o cliente marca sozinho pelo link da barbearia e o barbeiro só se preocupa com o corte.

Ver ao vivo Front-end API
project-barber-ui.vercel.app/agenda

O problema

Em barbearia pequena, o agendamento acontece no WhatsApp. O barbeiro para o corte para responder mensagem, confere horário de cabeça e ainda lida com cliente que esquece ou desmarca em cima da hora.

A solução

O Navalha dá a cada barbearia um link público de agendamento. O dono define serviços, preços e expediente uma vez; a partir daí os horários livres aparecem sozinhos para o cliente, que marca, remarca ou cancela sem criar conta.

Como funciona

Toda operação foi pensada para levar quatro toques ou menos.

  1. 01

    Cadastro da barbearia

    Nome da barbearia e do dono. Serviços entram com sugestões de um toque (corte, barba, sobrancelha).

  2. 02

    Expediente

    Dias da semana, horário de abertura e fechamento e duração do bloco. Repete toda semana.

  3. 03

    Link compartilhado

    O dono copia ou compartilha o link /b/<barbearia> no Instagram e no WhatsApp.

  4. 04

    Cliente agenda

    Escolhe serviço, dia e horário livre, digita o nome e confirma. Pode remarcar ou cancelar depois pelo mesmo link.

Funcionalidades

Agenda do dia

Faixa com 14 dias, contagem regressiva para o próximo cliente, faturamento previsto e blocos livres e ocupados.

Encaixe rápido

Toque num horário livre para encaixar quem chegou sem marcar.

Ausências

Bloqueie um período (almoço, imprevisto) e a API cancela os agendamentos que caem nele, com dupla confirmação.

Remarcação segura

O cliente vê o horário antigo e o novo antes de confirmar. Horário ocupado por outra pessoa some da grade na hora.

Sem conta para o cliente

Cada navegador guarda um token de dispositivo, que identifica a reserva sem pedir cadastro.

Histórico de mudanças

Toda reserva tem um log de criação, remarcação e cancelamento, e todas as tabelas têm histórico (SCD Tipo 4).

Por dentro

  • API em FastAPI com três camadas (API → Service → Repository), testada com pytest
  • Horários livres calculados a partir do expediente, agendamentos e ausências: nenhum "slot" é gravado no banco
  • Preço do serviço congelado no momento da reserva
  • Front-end Next.js renderizado no servidor; o token fica em cookie httpOnly e o navegador nunca chama a API direto
  • Cache opcional com Redis e deploy em Google Cloud Run
  • Next.js 16
  • React 19
  • Tailwind v4
  • FastAPI
  • Python 3.14
